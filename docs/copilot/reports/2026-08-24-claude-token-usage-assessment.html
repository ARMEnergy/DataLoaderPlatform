Executive Summary

High token usage is structural, not accidental. The current workflow enforces multi-stage agent orchestration with repeated ingestion of large instruction and documentation context. This compounds cost per loader task, especially when review/test loops are triggered.

Primary Drivers of Token Spend

CriticalMandatory multi-stage orchestration
  • Most loader tasks route through manager and full specialist chain.
  • Each stage adds prompt + artifact + summary overhead.
CriticalRepeated ingestion of large static guidance
  • Global conventions are rich and repeated across agent prompts.
  • Instruction payload is paid repeatedly across stage loops.
HighRe-reading large API and design documents
  • Documentation-first flow is valuable but expensive when over-applied.
  • Same large docs are often re-consulted by multiple agents for one task.
HighLoop amplification (review/test/fix)
  • Quality loops are correct, but broad context and long summaries increase cost per loop.
  • Solution-wide test defaults further increase loop footprint.

Proposed Solutions and Expected Savings

Proposal Process Change Expected Savings
Fast lane vs full lane routing Default to Coder -> Reviewer -> Tester for non-schema/non-API-shape changes; full chain only when needed. Existing loader changes: 60% to 80%
Prompt compression to checklist style Shorten CLAUDE + agent prompts; remove duplicated narrative while retaining hard quality gates. All scenarios: 20% to 35% incremental
Scoped testing default Run loader-scoped tests first; escalate to full-solution tests only for cross-cutting changes. Review/test loops: 30% to 50%
Response-size discipline Structured short outputs (files changed, decisions, risks, pass/fail); avoid large inline dumps. Loop stages: 10% to 25%
